# Pilot Test Plan for Lead A1: AI Parsing Cascade Evaluation

This document outlines the operational pilot test plan for lead A1. The objective is to evaluate a multi-tiered cascade architecture to lower job description parsing costs while maintaining accuracy equal to Claude Opus outputs.

---

## 1. Requirements from the Startup

To conduct this test safely and without taking security or legal risks, we request only static offline datasets:

1. **500 Representative Job Description Texts**: A JSON or CSV file containing raw job text from diverse industries, formatting styles, and length variations.
2. **Opus Answer Key**: The existing Claude Opus JSON parsing outputs for those exact 500 job descriptions to serve as ground truth.
3. **Target Schema Specification**: The explicit list of required fields, expected data types, and enum values (such as job title, experience level, required skills, salary range, location).
4. **Validation Rules**: Standard boundaries for required versus optional fields (for example, whether missing salary information is allowed).
5. **Data Transfer Boundary**: Kalpa Labs does not request or accept API keys, user credentials, or access to private scraping infrastructure. Kalpa Labs does not provide, assist with, or inspect scraping tools or LinkedIn extraction pipelines.

---

## 2. Test Execution Steps Using Free and Low-Cost Models

The test executes an automated multi-stage fallback pipeline on the 500 sample records:

1. **Dataset Ingestion and Pre-processing**: Load the 500 job descriptions, scrub remaining internal tags, and set up local validation logic.
2. **Tier 1 Extraction (Free Models)**: Run all 500 records through zero-cost or open-weights options (such as Llama 3 8B via free provider tiers [UNVERIFIED] or Gemini 1.5 Flash free tier [UNVERIFIED]).
3. **Schema and Completeness Verification**: Pass Tier 1 JSON outputs through an automated JSON Schema validator checking for required keys, correct data types, and non-null values.
4. **Tier 2 Escalation (Mid-tier Models)**: If Tier 1 fails schema validation or returns null on critical fields, pass the record to a intermediate model (such as Claude 3.5 Sonnet or GPT-4o-mini [UNVERIFIED]).
5. **Tier 3 Fallback (Opus)**: If Tier 2 fails secondary validation, route the record to Claude Opus as the final fallback mechanism.

---

## 3. Field-by-Field Scoring Methodology Against Opus Ground Truth

Accuracy is calculated by comparing candidate cascade outputs against the provided Opus answer key across five distinct data types:

1. **Exact Match (Categoricals)**: Fields like employment type (Full-time/Part-time) or remote status score 1 for an exact string match, 0 otherwise.
2. **List Overlap (Skills & Tools)**: Array fields use Jaccard similarity index (intersection divided by union of extracted skill terms) after lowercasing and trimming.
3. **Numeric Range Match**: Salary ranges and years of experience score 1 if both minimum and maximum bounds fall within 5% of the Opus reference values.
4. **Normalized String Similarity**: Fields like job title use normalized edit distance to account for minor spacing or capitalization differences.
5. **Completeness Score**: Ratio of successfully populated non-null mandatory fields compared to the ground truth output.
