# K093 · TruffleHog vs gitleaks: what each catches and a CI setup note (for A205)

1. **Detection Scope**: Gitleaks scans git repositories using regular expressions and structural rules to identify over 150 standard credential types, private keys, and high-entropy strings. TruffleHog scans code, commit history, and metadata against 800+ secret detectors (UNVERIFIED detector count), targeting both structured API tokens and unstructured credentials.

2. **Verified vs Unverified Findings**: Gitleaks provides passive pattern matching, flagging any string that matches a known secret format regardless of whether the credential is active. TruffleHog supports active verification (UNVERIFIED CLI flag syntax), attempting live API requests against provider endpoints to confirm if a detected secret is active. When active verification is disabled or unconfigured in CI, TruffleHog returns unverified regex findings similar to Gitleaks.

3. **Running TruffleHog on Git Diff in Actions**: To execute TruffleHog on pull request diffs without requiring secret keys or outbound API credentials, run the binary against the local repository path:
```yaml
- uses: actions/checkout@v4
  with:
    fetch-depth: 0
- name: TruffleHog diff scan
  run: |
    trufflehog git file://. --since-commit ${{ github.event.pull_request.base.sha }} --no-verification
```
*(Note: `--no-verification` flag syntax is UNVERIFIED against official vendor docs).*

4. **False-Positive Management**: Gitleaks suppresses known false positives via a `.gitleaksignore` file containing secret fingerprints or commit hashes, as well as inline `#gitleaks:allow` comments. TruffleHog manages exclusions using a `.trufflehogignore` path file or execution flags such as `--exclude-paths` (UNVERIFIED flag specification).

5. **CI Selection Note for A205**: Gitleaks (MIT license) is currently pinned in `.github/workflows/quality.yml` at `v8.30.1`, running locally in Go without external API traffic. TruffleHog (AGPL-3.0 license for the open-source CLI) offers optional live credential verification, but adds binary footprint and network evaluation overhead when integrated into automated pull request gates.
