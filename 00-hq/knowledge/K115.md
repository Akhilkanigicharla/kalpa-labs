# K115 · A239 goldfish review: cf-runner design

_Agent: Forge · model gemini-flash-lite-latest · Vigil: PASS (qwen/qwen3.8-27b) · 2026-11-19T10:47:09Z · status: needs Akhil/Claude review_

1. BLOCKER: Cloudflare Workers Free plan limits subrequests to 50 per invocation, but reading 9 queue files, fetching up to 3 context files, calling model endpoints, and using the GitHub Git Data API (read ref, create tree, create commit, patch ref) will easily exceed this quota or the 10ms CPU time limit for complex JSON parsing and string concatenation. Fix: Batch queue file reads using a single tree API call or reduce world file count.

2. BLOCKER: The GitHub Git Data API sequence (`PATCH ref` with `force: false`) handles concurrent pushes by returning a 422 error, but the runner fails silently without re-fetching the latest `main` ref and retrying the commit within the same invocation, leaving stale tasks untouched until the next 30-minute cron. Fix: Implement a single-retry loop that re-fetches the current `main` commit SHA on a 422 response.

3. MAJOR: The cron trigger `5,35 * * * *` consumes 2 of the remaining free tier triggers (leaving only 1 for future use), and overlaps closely with `cf-timer` dispatches if GitHub Actions jobs run long, causing potential race conditions on the repository state despite ref checks. Fix: Reduce to a single daily or hourly cron trigger (`35 * * * *`) to preserve Cloudflare Free plan quotas.

4. MAJOR: Model API timeouts are set to 60 seconds per call with `AbortController`, but Cloudflare Workers Free requests have a strict 30-second wall-clock time limit for incoming HTTP requests (though scheduled events have a slightly higher limit, multi-model fallback chains can easily exceed it). Fix: Lower individual model fetch timeouts to 8 seconds and limit fallbacks to two models maximum.

5. MAJOR: The `test-dev.sh` script relies on a local mock server (`mock.mjs`), but there is no verification that local workerd execution parity matches production Workers runtime behavior for environment variable bindings and fetch TLS handling. Fix: Add a dry-run production integration test using `wrangler tail` or explicit staging assertions before live deployment.

6. MINOR: The rule stating "model output straight to main -> status is review" still commits unvalidated LLM-generated code directly to the repository history under a bot author, risking supply chain pollution if prompt injection occurs in stale queue tasks. Fix: Add a strict regex validation step on the output file path and content headers before the commit tree is built.

7. MINOR: The kill switch relies exclusively on an environment variable `ENABLED = "1"` checked inside the script, but if the variable is omitted or undefined due to a wrangler config typo, it defaults to truthy and executes unintended writes. Fix: Invert the default logic so the Worker halts unless `ENABLED` is explicitly set to `"1"`.
