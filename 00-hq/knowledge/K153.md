**✦ Encryption‑options for pg_dump in GitHub Actions ✦**  

Below‑the‑line you’ll find three **free‑tool** choices – *age*, *GPG symmetric* and *OpenSSL enc* – each wrapped in a single‑line command, the licence that governs it, the way the secret key lives in a **GitHub Secret**, and the matching restore command.  All URLs point to the official docs; anything not visible in the repo is marked **UNVERIFIED**.

---  

### 1️⃣ **age** (“**A** Go Encrypt”)  
- **Licence** – *BSD‑3‑Clause* (see <https://github.com/FiloSottile/age/blob/master/LICENSE>)  
- **Encrypt command** – ```bash
pg_dump -Fc mydb | age -r ${{ secrets.AGE_RECIPIENT }} -o dump.age
```  
- **Secret handling** – store the **public key** of the recipient as `AGE_RECIPIENT` (base‑64); the private key lives off‑repo, loaded at runtime via a separate secret `AGE_PRIVATE_KEY` (UNVERIFIED – repo does not contain a key)  
- **Restore command** – ```bash
age -d -i ${{ secrets.AGE_PRIVATE_KEY }} -o - dump.age | pg_restore -d mydb
```  

*Docs:* <https://github.com/FiloSottile/age>  

---  

### 2️⃣ **GPG symmetric**  
- **Licence** – *GPL‑3.0* (see <https://www.gnu.org/licenses/gpl-3.0.html>)  
- **Encrypt command** – ```bash
pg_dump -Fc mydb | gpg --symmetric --cipher-algo AES256 --batch --passphrase "$GPG_PASS" -o dump.gpg
```  
- **Secret handling** – the passphrase is saved as a GitHub secret named `GPG_PASS` (UNVERIFIED – no reference in repo)  
- **Restore command** – ```bash
gpg --batch --yes --passphrase "$GPG_PASS" -d dump.gpg | pg_restore -d mydb
```  

*Docs:* <https://gnupg.org/documentation/>  

---  

### 3️⃣ **OpenSSL enc**  
- **Licence** – *Apache‑2.0* (see <https://www.openssl.org/source/license.html>)  
- **Encrypt command** – ```bash
pg_dump -Fc mydb | openssl enc -aes-256-cbc -salt -pbkdf2 -pass env:OPENSSL_PASS -out dump.enc
```  
- **Secret handling** – the password is kept in a GitHub secret `OPENSSL_PASS` (UNVERIFIED – repo does not reference it)  
- **Restore command** – ```bash
openssl enc -d -aes-256-cbc -salt -pbkdf2 -pass env:OPENSSL_PASS -in dump.enc | pg_restore -d mydb
```  

*Docs:* <https://www.openssl.org/docs/man1.1.1/man1/enc.html>

## 📅 Monthly restore‑test (5 steps)  

1. **Spin‑up** a throwaway Postgres container (e.g. `docker run --rm -e POSTGRES_PASSWORD=tmp -p 5432:5432 postgres:15`).  
2. **Download** the 7‑day private artifact from the previous night’s workflow (`gh run download --name pg-backup`).  
3. **Decrypt** the dump with the matching tool (age | gpg | openssl) using the secret stored in the workflow run.  
4. **Restore** into the container: `pg_restore -d testdb -U postgres -h localhost -Fc <decrypted‑file>`.  
5. **Validate** by running a quick query (`SELECT count(*) FROM important_table;`) and then **tear‑down** the container (`docker stop <id>`).  

*All steps respect the 5‑item limit, use only free software, and keep secrets out of the repo.*
