### Hand Accessibility Checklist (390px Mobile View)

1. **Screen Reader Labels**
   * **What to do:** Turn on TalkBack or VoiceOver. Swipe through all controls (buttons, inputs, links, images).
   * **Pass criteria:** Every control has a spoken label that describes its function. Decorative images are ignored (`alt=""` or `aria-hidden="true"`).
   * **WCAG 2.2:** 1.1.1 Non-text Content (A), 4.1.2 Name, Role, Value (A).

2. **Keyboard Focus Order**
   * **What to do:** Connect a Bluetooth keyboard or use screen reader navigation. Press Tab through the entire app.
   * **Pass criteria:** Focus moves logically from top to bottom, left to right. No hidden elements receive focus, and focus is never trapped.
   * **WCAG 2.2:** 2.4.3 Focus Order (A).

3. **Visible Focus Indicator**
   * **What to do:** Tab through every interactive element and watch the screen.
   * **Pass criteria:** A visible outline or high-contrast box surrounds the element currently focused.
   * **WCAG 2.2:** 2.4.7 Focus Visible (AA), 2.4.13 Focus Appearance (AAA/2.2 AA draft criteria).

4. **Colour Contrast (Normal Text)**
   * **What to do:** Inspect body text, field labels, and button labels using a color picker tool.
   * **Pass criteria:** Text under 18pt (or 14pt bold) has a contrast ratio of at least 4.5:1 against its background.
   * **WCAG 2.2:** 1.4.3 Contrast (Minimum) (AA).

5. **Colour Contrast (UI Components & Large Text)**
   * **What to do:** Inspect icons, borders of input fields, buttons, and large headings.
   * **Pass criteria:** Graphical components, visual boundaries of inputs, and text above 18pt have at least a 3:1 contrast ratio.
   * **WCAG 2.2:** 1.4.11 Non-text Contrast (AA).

6. **Text Zoom (200%)**
   * **What to do:** Increase text size to 200% in browser settings on a 390px screen.
   * **Pass criteria:** No text overlaps, clips, or gets cut off. No horizontal scrolling occurs for text blocks.
   * **WCAG 2.2:** 1.4.4 Resize Text (AA).

7. **Touch Target Size**
   * **What to do:** Inspect buttons, pills, tabs, and form controls using browser DevTools set to 390px device width.
   * **Pass criteria:** Clickable area for every control is at least 44×44 CSS pixels (or has sufficient spacing around smaller targets to equal 24×24 minimum under 2.2).
   * **WCAG 2.2:** 2.5.8 Target Size (Minimum) (AA), 2.5.5 Target Size (Enhanced) (AAA).

8. **Language Attributes for Multilingual Text**
   * **What to do:** Inspect HTML elements containing Indian script text (Telugu/Hindi).
   * **Pass criteria:** Text in non-English scripts is wrapped in elements with correct `lang` attributes (e.g., `<span lang="te">` or `<span lang="hi">`).
   * **WCAG 2.2:** 3.1.2 Language of Parts (AA).

9. **Form Error Messages & Association**
   * **What to do:** Trigger a validation error on forms (e.g., submit empty required fields).
   * **Pass criteria:** Error message is announced by screen readers (`role="alert"` or `aria-live`), and input points to its error via `aria-describedby` or explicit label association.
   * **WCAG 2.2:** 3.3.1 Error Identification (A), 3.3.3 Error Suggestion (AA).

10. **Reduced Motion Support**
    * **What to do:** Enable "Reduce Motion" in phone OS settings and trigger animations/page transitions.
    * **Pass criteria:** Non-essential animations, sliding views, and zooms are disabled or replaced with simple fades via `@media (prefers-reduced-motion: reduce)`.
    * **WCAG 2.2:** 2.3.3 Animation from Interactions (AAA).

11. **Orientation Support**
    * **What to do:** Rotate the phone from portrait to landscape mode at 390px base equivalent.
    * **Pass criteria:** App displays cleanly in both orientations without locking view or blocking content.
    * **WCAG 2.2:** 1.3.4 Orientation (AA).

12. **Use of Colour Alone**
    * **What to do:** Check status badges, active tab highlights, and error states in grayscale mode.
    * **Pass criteria:** Information conveyed by color is also indicated by text, icons, bold weight, or underline.
    * **WCAG 2.2:** 1.4.1 Use of Color (A).

13. **Dynamic Content Announcements (Live Regions)**
    * **What to do:** Trigger UI updates without page reloads (e.g., dynamic result counts, state updates).
    * **Pass criteria:** Screen readers automatically read updated content using `aria-live="polite"` or `aria-live="assertive"`.
    * **WCAG 2.2:** 4.1.3 Status Messages (AA).

14. **Accessible Canvas Content**
    * **What to do:** Inspect HTML `<canvas>` elements used for editing or graphics.
    * **Pass criteria:** Canvas has an informative `aria-label`, inner fallback text, or external controls that duplicate canvas actions for screen reader users.
    * **WCAG 2.2:** 1.1.1 Non-text Content (A).

15. **HTML Page Language Declaration**
    * **What to do:** Inspect the top `<html>` tag of the document.
    * **Pass criteria:** Primary language of the document is correctly declared (e.g., `<html lang="en">`).
    * **WCAG 2.2:** 3.1.1 Language of Page (A).

### App-Specific Fail Risks (Based on HTML Inspection)

* **`02-jobcard/apps/jyotish`**: Most likely to fail **Check 8** (dynamic script switches for Telugu/Hindi lack inline `lang` tags on rendered content output), **Check 9** (form errors use `role="alert"` but inputs lack `aria-describedby` linking directly to error element IDs), and **Check 7** (language switcher pills `.pill` and date/time inputs may sit under 44px height on tight 390px multi-column grid layouts like `.row3`).
* **`02-jobcard/apps/photo-studio`**: Most likely to fail **Check 14** (interactive head box on `<canvas id="editor">` cannot be dragged via screen reader or keyboard), **Check 7** (range slider `<input type="range" id="bgThr">` and narrow buttons are difficult to adjust on small touchscreens), and **Check 9** (file validation error `#fileErr` is disconnected from input `#file` with no `aria-describedby`).
* **`02-jobcard/apps/bhasha-kids`**: Most likely to fail **Check 8** (app container `<main id="app">` rendered dynamically with Telugu/Hindi content stays inside top-level `<html lang="en">` without script-level `lang` updates), **Check 2** (dynamically injected lesson content risk losing screen reader focus state), and **Check 7** (kid-oriented control target sizes are unverified in standard CSS fallback styles UNVERIFIED).
