# A2: Open-source voice AI for Indian businesses (BotBhai voice)

Researched 2026-10-13 by GitHub Research Agent 2. Stars come from ecosyste.ms. Last-commit dates and licences come from shallow clones. Model licences come from the Hugging Face API.

## Summary
BotBhai's current stack (Pipecat 1.12, Sarvam, Groq) is the right choice. The biggest gains come from Pipecat 1.12 features we don't use yet, not from switching frameworks. There is also one real bug: in Pipecat 1.12, `FastAPIWebsocketParams(vad_analyzer=...)` is **silently discarded** because the field no longer exists. That means BotBhai currently runs **with no VAD**, which hurts turn-taking and barge-in. Pipecat 1.12 already bundles the smart-turn v3.2 CPU model, a voicemail detector and an offline eval harness, and all three are BSD-2. Bolna (MIT, India-focused) is the best codebase to learn from for Indian telephony, voicemail handling and language switching. The open Indian TTS models are mostly 0.35–3.8B parameters and need a GPU for real-time calls, so we keep Sarvam for live calls.

## Tried it

1. **smart-turn v3.2-cpu on Indian phone audio.** I used a fresh venv (`uv venv; uv pip install numpy onnxruntime transformers soundfile`) and downloaded the 8.7 MB ONNX from HF. Test clips were Google-TTS Telugu, Hindi and English sentences, passed through **8 kHz μ-law and back to 16 kHz** to mimic a Plivo/Exotel line. Incomplete cases were trailing phrases plus complete sentences cut at 55%.
   - Result: **15/18 correct. Median 47 ms per inference on 1 CPU thread.**
   - Hindi: 6/6, with confident scores (0.91–0.98 complete, ≤0.08 incomplete).
   - Telugu: 6/8, with marginal scores. A short question, "మీ జిమ్ ఫీజు ఎంత?", came back as *incomplete* (p=0.16). The phrase "నాకు రేపు సాయంత్రం" came back as *complete* (p=0.63).
   - English: "I want to book a haircut for" came back as *complete* (p=0.55).
   - Caveat: these are synthetic voices, not real callers.
   - Implication: Pipecat's default smart-turn fallback is `stop_secs=3`, so a Telugu caller's short question can wait **3 s** before the bot replies. Lower it to about 1.2–1.5 s.
2. **Pipecat 1.12 eval harness, fully offline.** Fresh venv: `uv pip install "pipecat-ai[cli,silero,websocket,groq,sarvam]==1.12.0"`. I wrote a toy bot (`-t eval` transport, a rule-based fake LLM, no API keys) and a scripted Tenglish scenario (`"Naaku repu haircut kavali"` expects `text_contains: "ye roju"`). I ran `pipecat eval run botbhai_smoke.yaml --bot-url ws://localhost:7861 -v` and got **1/1 passed in 0.3 s**. Scenarios support `function_call` expectations (for example "the bot calls `book` with date X") and LLM-simulated callers. The judge defaults to Ollama but is configurable. Gotchas: it needs the `[cli]` extra, and the flag is `--bot-url`, not `--url`.
3. **Bolna test suite.** Fresh Python 3.12 venv, `uv pip install -r requirements.txt pytest pytest-asyncio` (6 s). `pytest tests/test_voicemail_gate.py` gave 13 passed. The full suite (`pytest --ignore=tests/manual`) gave **2,326 passed, 1 skipped in 78 s**. Useful code to read: `bolna/agent_manager/voicemail_handler.py`, the `VOICEMAIL_DETECTION_PROMPT` in `bolna/prompts.py` (it treats Hindi "यह कॉल रिकॉर्ड की जा रही है" and "Haan bolo" as a human, not voicemail), `bolna/lid/sarvam.py` (detects the caller's language from Sarvam saaras:v3 with `language-code=unknown` at no extra latency), and `input_handlers/telephony_providers/{plivo,exotel,vobiz}.py`.
4. **Static check of agent.py against Pipecat 1.12.** In the fresh venv, `FastAPIWebsocketParams(vad_analyzer=SileroVADAnalyzer())` returns `'vad_analyzer' in model_fields == False` and `p.vad_analyzer → None`, so **the VAD is dropped**. In 1.12 the VAD lives on `LLMUserAggregatorParams(vad_analyzer=...)`. I also confirmed that the proposed wiring below constructs without errors in 1.12.
5. **Not run:** Indic Parler-TTS (3.8 GB), IndicF5, Svara, Veena and IndicConformer. These are multi-GB models that need a GPU for real-time use. Try them on Colab if offline voice-note TTS is wanted.

Clones and venvs were deleted afterwards.

## Concrete changes for Kalpa Labs

- **Fix the VAD bug in `01-studio/botbhai/voice/agent.py` `run_call()`.** Remove `vad_analyzer` from `FastAPIWebsocketParams`. Instead, pass `LLMContextAggregatorPair(context, user_params=LLMUserAggregatorParams(vad_analyzer=SileroVADAnalyzer(params=VADParams(stop_secs=0.2)), user_turn_strategies=UserTurnStrategies(stop=[TurnAnalyzerUserTurnStopStrategy(turn_analyzer=LocalSmartTurnAnalyzerV3(params=SmartTurnParams(stop_secs=1.5)))])))`. This turns barge-in back on and caps the Telugu misjudgement delay at 1.5 s instead of 3 s or 5 s.
- **Set the Sarvam TTS language per client.** Pipecat's `SarvamTTSService` defaults to `Language.EN` (en-IN), and `agent.py` never sets a language, so Telugu or Hindi replies are likely being voiced through the en-IN path. Add `language=` from client config (`te-IN` or `hi-IN`) in `SarvamTTSService.Settings`, and add a `language` field in `prompt.voice_profile()`. Later, copy Bolna's approach: read the caller's language from Sarvam STT and push a `TTSUpdateSettingsFrame` to switch mid-call.
- **Add India-aware voicemail and carrier-message detection to outbound calls** using `pipecat.extensions.voicemail.VoicemailDetector(classifier=LLMClassifier(llm=Groq llama-3.1-8b-instant, instructions=...))`. Put `detector.detector()` after STT and `detector.gate()` after TTS, for outbound calls only. Base the instructions on Bolna's prompt plus Indian carrier lines ("switched off", "not reachable", "number does not exist", in Hindi and Telugu). Call-recording notices count as human. On `on_voicemail_detected`, end the call and queue the existing WhatsApp follow-up. Keep Plivo `machine_detection` as a backup.
- **Add `01-studio/botbhai/voice/evals/`** with scripted YAML scenarios per setup: salon booking in Tenglish, a slot-taken retry, the callback tool, and "are you a human?". Use `function_call` expectations on `book` and `request_callback`, with a small `-t eval` entry point that reuses `run_call` with a mock Supabase. Run it in GitHub Actions on every change to `prompt.py`. Text mode needs no Sarvam credits.
- **Lower Telugu latency risk with `prompt.py` rules.** The system prompt should tell the bot to ask closed questions in the caller's language, which gives short, clearly finished answers. Log `enable_metrics` turn latency to Supabase so we can see real smart-turn misses before tuning further.
- **Licence hygiene in `voice/requirements.txt` and docs.** Never add piper1-gpl, MMS-TTS (CC-BY-NC), TEN or the LiveKit turn-detector. Record that IndicF5's code has no licence file and that Svara and Veena are Llama-derived, and get explicit sign-off before using any of them commercially.
