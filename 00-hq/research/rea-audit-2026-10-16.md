# REA outsider audit of Kalpa Labs (16 Oct 2026) and what was fixed

**Audit:** run by Claude Code on Akhil's PC with REA (morluto/rea, MIT) plus gitleaks and a static review, at commit `dc7b408`. REA analysed the Tab Lifeboat build, the BotBhai serverless functions and the JobCard library (0 parse failures); websites were checked as built files. **No real secrets** were found in any file or in all 54 commits.
**Fixes:** made in the cloud session the same day (A48). Status per finding below.

| # | Product | Finding | Severity | Status |
|---|---|---|---|---|
| 1 | BotBhai | Meta Lead Ads webhook accepted unsigned posts when `WA_APP_SECRET` was unset | High | ✅ Fixed: fails closed like `whatsapp.js` (`ALLOW_UNSIGNED=1` only for a local test), non-POST → 405 (test) |
| 2 | BotBhai | `page_id` went into the DB query unencoded | Medium | ✅ Fixed: page and lead ids must be digits, then encoded (test) |
| 3 | BotBhai | Website chat had no rate limit; anyone could fill slots and spam owner alerts | High | ✅ Fixed: DB-backed limits (`rate_hit` RPC) 30 msgs/visitor and 120/IP per 10 min, max 3 owner alerts per visitor per hour, **one open booking per web visitor** (a 2nd booking moves the 1st) (4 tests). Cloudflare Turnstile is a later option (A50) |
| 4 | BotBhai | Dashboard token in the URL | Medium | ✅ Fixed: API takes `Authorization: Bearer` only (test); the dashboard link now carries the token after `#` (never sent to the server), and an old `?token=` link is wiped from the address bar |
| 5 | BotBhai | `Access-Control-Allow-Origin: *` on the leads API | Low | ✅ Fixed: no CORS header on private endpoints (test) |
| 6 | BotBhai | DB error bodies (customer text) written to logs | Low | ✅ Fixed: status + error code + table only (test) |
| 7 | BotBhai | Voice server key defaulted to "" | Low | ✅ Fixed: voice reply skipped when `VOICE_SERVER_KEY` is missing |
