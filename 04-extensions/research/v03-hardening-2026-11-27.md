Scope: v0.3 features in build (popup search, edit a saved session, save window / picked tabs from a right-click menu and a keyboard shortcut, importers for user-supplied Edge Collections CSV, Pocket CSV/HTML, Toby JSON and bookmarks HTML, Markdown / plain-text export, stale-snapshot warning on the icon, restore that skips tabs already open, crash/update restore banner).
Method: Chrome, OWASP, W3C and MDN pages fetched on 27–28 Nov 2026, with at least two sources per point. Code read at commit `435fe85f` (v0.2.0) **plus the uncommitted v0.3 work in the tree** (10 files changed by the parallel build agents while this review ran). ## 0. Results first

### What builders must follow (short form)
1. **Never put user data into HTML.** No `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `document.write` or `DOMParser` nodes inserted into the page. Use `textContent` and `createElement`. Today the code has **zero** HTML sinks. Keep it that way.
2. **URL allowlist everywhere** (import, store, restore, link, export): parse with `new URL()`, and keep only `http:` and `https:` URLs. Every other scheme (chrome, edge, about, file, data, javascript, blob, view-source, chrome-extension) is "can't reopen". Show it as plain text with a count, never as a link.
3. **Limits:** import file ≤ 20 MB; ≤ 20,000 tabs and ≤ 1,000 sessions per import; JSON depth ≤ 32; URL ≤ 8,192 chars; title ≤ 1,000; session/group name ≤ 200. Restore asks first above 100 tabs.
4. **Every message is checked**: known `type`, field types and caps (`lib/messages.ts` `checkMsg`) and sender is our own page (`fromUs`). Every new v0.3 message type goes into `TYPES`, and its test goes into the messages suite.
5. **Exports are escaped:** CSV cells always quoted with `"` doubled, plus `'` prefix when a cell starts with `= + - @`, tab or CR (and full-width `＝ ＋ － ＠`). Markdown titles are escaped, URLs written as `<…>` and http(s) only.
6. **No new warning permissions in v0.3.** `contextMenus` has no warning, and `commands` is a manifest key, not a permission. **Do not add `favicon` or `sessions`:** they add install warnings, and Chrome disables the extension on update until the user accepts.
7. **Storage failures are handled:** catch `QuotaExceededError` on every IndexedDB write. Tell the user in plain words, keep their input, and set the icon warning.
8. **WCAG 2.2 AA in popup + options:** focus never hidden by the undo bar or banner (2.4.11), targets ≥ 24 px (Kalpa uses 44), and a click alternative for every drag (2.5.7). Status messages use `aria-live`.

No CRITICAL issue found. No HTML sink, no remote code, no host permissions, no content scripts, no `web_accessible_resources`, no `externally_connectable`. Incognito windows are skipped. Search results link only http(s) URLs.

## 1. Research findings (each point has 2+ sources, fetched 27–28 Nov 2026)

### 1.1 CSP for extension pages
- Default MV3 `extension_pages` CSP is `script-src 'self'; object-src 'self';`. The minimum is `script-src 'self' 'wasm-unsafe-eval'; object-src 'self';`, and the CSP "cannot be relaxed beyond this minimum". Adding `'unsafe-eval'` is rejected at install. [Chrome: Manifest CSP](https://developer.chrome.com/docs/extensions/reference/manifest/content-security-policy)
- "Include a content security policy for the extension in the manifest to prevent cross-site scripting attacks" (example uses `default-src 'self'`). [Chrome: Stay secure](https://developer.chrome.com/docs/extensions/develop/security-privacy/stay-secure)
- OWASP: configure `content_security_policy.extension_pages`, load scripts only from the package, keep inline scripts blocked. [OWASP Browser Extension Vulnerabilities Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Browser_Extension_Vulnerabilities_Cheat_Sheet.html)
- **For us:** no inline scripts or handlers in `popup/index.html` / `options/index.html` (checked). Make the CSP explicit and add `img-src`/`connect-src` (see audit).

### 1.2 Message passing
- "Assume that messages from a content script might have been crafted by an attacker"; validate and sanitize; limit privileged actions; use `JSON.parse`/`innerText`, avoid `eval`/`innerHTML`. **Max message size is 64 MiB.** [Chrome: Messaging](https://developer.chrome.com/docs/extensions/develop/concepts/messaging)
- "Always validate that the sender matches a trusted source." [Chrome: Stay secure](https://developer.chrome.com/docs/extensions/develop/security-privacy/stay-secure)
- OWASP: "Treat all incoming messages as untrusted input"; validate `sender.id` and `sender.url`, and allow-list actions and parameters. [OWASP cheat sheet](https://cheatsheetseries.owasp.org/cheatsheets/Browser_Extension_Vulnerabilities_Cheat_Sheet.html)
- **For us:** we have no content scripts and no `externally_connectable`, so only our pages can send today. `checkMsg` + `fromUs` are defence in depth for the day a content script is added. Keep both.

### 1.3 web_accessible_resources and fingerprinting
- "By default no resources are web accessible". Exposing any resource lets sites detect the extension and attack bugs in it. `use_dynamic_url` rotates the URL per session. [Chrome: web_accessible_resources](https://developer.chrome.com/docs/extensions/reference/manifest/web-accessible-resources)
- "The more web accessible resources available, the more avenues a potential attacker can exploit." [Chrome: Stay secure](https://developer.chrome.com/docs/extensions/develop/security-privacy/stay-secure)
- **For us:** keep it **absent** in v0.3. Nothing in the feature list needs it. It also means web pages cannot frame our pages (clickjacking, check 83).

- Adding a permission with a new warning in an update: "the extension will be disabled until the user accepts the new permission". [Chrome: Permission warnings](https://developer.chrome.com/docs/extensions/develop/concepts/permission-warnings)
- OWASP + Chrome both say least privilege, with optional permissions where possible ([OWASP](https://cheatsheetseries.owasp.org/cheatsheets/Browser_Extension_Vulnerabilities_Cheat_Sheet.html), [Stay secure](https://developer.chrome.com/docs/extensions/develop/security-privacy/stay-secure)).
- **Commands rules:** at most **4** suggested shortcuts. Each must include **Ctrl or Alt** (not Ctrl+Alt). Chrome/OS shortcuts always win. - **Context menu rules:** at most **6** top-level items in the `action` menu (`ACTION_MENU_TOP_LEVEL_LIMIT`). Contexts `action` (toolbar icon) and `tab` (tab strip) are listed. Use `contextMenus.onClicked`, because `onclick` is not available in a service worker. Ids must be unique, and create errors only appear in `runtime.lastError`. [contextMenus API](https://developer.chrome.com/docs/extensions/reference/api/contextMenus). The `tab` context is from the docs fetched today; **test it in the target Chrome** before relying on it.

### 1.5 URL schemes on restore
- Chrome restricted extension navigation to `file:` URLs through tabs/windows APIs from **Chromium 118** (unless the user enables "Allow access to file URLs"). It extended the **`javascript:` block to all tabs/windows API methods from Chrome 117**. [chromium-extensions announcement](https://groups.google.com/a/chromium.org/g/chromium-extensions/c/ZtCvVISQU54/m/tOjjlzkfAgAJ)
- Firefox refuses `chrome:`, `javascript:`, `data:`, `file:` and privileged `about:` URLs in `tabs.create`. [MDN tabs.create](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/tabs/create)
- Chrome allowed `tabs.create({url:'chrome://settings/…'})` in a 2011 thread ([chromium-extensions](https://groups.google.com/a/chromium.org/g/chromium-extensions/c/Nk5Pj7yrsmQ)). **Unverified today** which `chrome://` pages are allowed now.
- **Decision for v0.3:** restore **http/https only** (the current `restorable()`). No `chrome://` allowlist: low value (mostly `chrome://newtab`), behaviour differs across browsers, and it is unverified. Show "3 browser pages can't be reopened by extensions" with the address as copyable text.

### 1.6 Known attacks 2024–2026 that apply to us
- **Malicious update through a hijacked developer account (Cyberhaven, Dec 2024).** A phishing email posing as the Chrome Web Store got an employee to "authorize a malicious OAuth application". Malicious version 24.10.4 was published on 25 Dec. It could steal "authenticated sessions and cookies". At least 5 other extensions were hit. [TechCrunch](https://techcrunch.com/2024/12/27/cyberhaven-says-it-was-hacked-to-publish-a-malicious-update-to-its-chrome-extension), [SecurityWeek](https://www.securityweek.com/several-chrome-extensions-compromised-in-supply-chain-attack/)
- **Clean-then-malicious updates (RedDirection, Jul 2025).** 18 Chrome/Edge extensions, 2.3 M users. Some had been clean for years and carried the verified badge before an update made them track URLs and hijack sessions. Updates installed silently. [The Register](https://www.theregister.com/2025/07/08/browser_hijacking_campaign/), [CSO Online](https://www.csoonline.com/article/4019477/verified-featured-and-malicious-reddirection-campaign-reveals-browser-marketplace-failures.html) (search result, not fetched)
- **npm supply chain (Shai-Hulud, Sep 2025).** A self-replicating worm hit 500+ npm packages and stole GitHub/npm/cloud tokens. CISA says: pin versions, review lock files, rotate credentials, and use phishing-resistant MFA on developer accounts. [CISA alert](https://www.cisa.gov/news-events/alerts/2025/09/23/widespread-supply-chain-compromise-impacting-npm-ecosystem), [Wiz / Sonatype coverage of the chalk/debug compromise](https://www.sonatype.com/blog/npm-chalk-and-debug-packages-hit-in-software-supply-chain-attack) (search result)
- **XSS through tab titles/URLs.** Titles come from any website, and imported files are attacker-controlled. Chrome and OWASP both say: no `innerHTML`, use text APIs ([Messaging](https://developer.chrome.com/docs/extensions/develop/concepts/messaging), [OWASP](https://cheatsheetseries.owasp.org/cheatsheets/Browser_Extension_Vulnerabilities_Cheat_Sheet.html)). `DOMParser` output is inert until inserted, then "scripts in the new body will run". It can also fetch `<img>`/`<iframe>` resources. [MDN parseFromString](https://developer.mozilla.org/en-US/docs/Web/API/DOMParser/parseFromString)
- **CSV formula injection on export.** Trigger characters are `=`, `+`, `-`, `@`, tab (0x09), CR (0x0D), LF and full-width variants. The fix: quote the cell, double the `"`, prefix with `'`. Note this "may not remain reliable in Microsoft Excel after saving and re-opening". [OWASP WSTG CSV injection](https://owasp.org/www-project-web-security-testing-guide/latest/4-Web_Application_Security_Testing/07-Input_Validation_Testing/21-Testing_for_CSV_Injection), [Telerik formula-injection docs](https://www.telerik.com/kendo-react-ui-develop/components/grid/export/csv-export/formula-injection)
- **Prototype pollution from imported JSON.** `JSON.parse` makes `__proto__` a plain own property, which is harmless until it is copied with `Object.assign`/`for…in`. Spread is safe. Defences: schema-validate, reject `__proto__`/`constructor`/`prototype` as dynamic keys, use `Map` or `Object.create(null)`. [MDN Prototype pollution](https://developer.mozilla.org/en-US/docs/Web/Security/Attacks/Prototype_pollution), [OWASP Prototype Pollution Prevention](https://cheatsheetseries.owasp.org/cheatsheets/Prototype_Pollution_Prevention_Cheat_Sheet.html)
- **Zip/JSON bombs and size.** Messages cap at 64 MiB ([Messaging](https://developer.chrome.com/docs/extensions/develop/concepts/messaging)). The ~2 MB data-URL limit is discussed in the [chromium-dev thread](https://groups.google.com/a/chromium.org/g/chromium-dev/c/zYYSVvn6a5M). **Pocket:** export was a CSV, and exports closed on 12 Nov 2025 ([Mozilla support](https://support.mozilla.org/en-US/kb/exporting-your-pocket-list)). Files are named `part_000001.csv` with `title,url,time_added,tags,status` ([gist](https://gist.github.com/thesamovar/836a8a0359b7eeb33db25ffe14baf411)). So users only have files they already downloaded. **Accept the CSV and ask them to unzip a .zip** (no zip parser means no zip bomb).

### 1.7 Chrome Web Store policy points
- "An extension must have a single purpose that is narrow and easy to understand." Collect/use only data "necessary for the extension's disclosed single purpose". "Collection and use of web browsing activity is prohibited, except to the extent required for a user-facing feature" that is described in the listing and UI. No obfuscation, and no remotely hosted logic. [CWS Program Policies](https://developer.chrome.com/docs/webstore/program-policies/policies)
- Limited Use: no transfers or sale, no human reading of user data except with consent, security or law. [CWS Limited Use](https://developer.chrome.com/docs/webstore/program-policies/limited-use)
- **For us:** importers, exports, menu and shortcut all serve "save and restore tabs", so they stay within the single purpose. Update the privacy page: "imported files are read on your computer and never uploaded". No remote feature flags or remote config that changes behaviour.

### 1.8 Storage quotas
- `storage.local` has a 10 MB limit, ignored with `unlimitedStorage`. `storage.sync` allows 102,400 bytes total, 8,192 per item, 512 items and 120 writes/min. Over-limit writes "fail immediately". [chrome.storage](https://developer.chrome.com/docs/extensions/reference/api/storage)
- IndexedDB over quota throws `QuotaExceededError`. Chromium origins may use up to 60% of disk. `navigator.storage.persist()` avoids eviction, and `estimate()` reports usage. [MDN Storage quotas](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)
- **For us:** tab data stays in IndexedDB. Small settings go in `storage.local`, and nothing goes in `storage.sync`. Catch `QuotaExceededError`.

### 1.9 Accessibility (WCAG 2.2) for popups
- New in 2.2 at A/AA: 2.4.11 Focus Not Obscured (Minimum), 2.5.7 Dragging Movements, 2.5.8 Target Size (Minimum), 3.2.6 Consistent Help, 3.3.7 Redundant Entry, 3.3.8 Accessible Authentication. 4.1.1 Parsing was removed. [W3C What's new in 2.2](https://www.w3.org/WAI/standards-guidelines/wcag/new-in-22/)
- 2.5.8: targets "at least 24 by 24 CSS pixels" or spaced. 44×44 is the enhanced level. [W3C Understanding 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)
- Popup must be between 25×25 and 800×600. Badge text should be ≤ 4 characters, and `setTitle` sets the tooltip. [chrome.action](https://developer.chrome.com/docs/extensions/reference/api/action)

## 2. v0.3 checklist: exact rules

### 2.1 URLs (one helper, used everywhere)
- `safeUrl(s): string | null` = `s.length ≤ 8192`, `new URL(s)` succeeds, `protocol ∈ {"http:","https:"}`. Return `u.href`. Use it in **import, backup parse, edit (add/move tab), restore, export, links in UI**. `restorable()` in `lib/model.ts` stays the single source. Extend it, don't fork it.
- Show the **host from `new URL()`** next to titles in search and edit lists, so `https://google.com@evil.example` shows `evil.example`.
- Links rendered in our pages: `<a>` only for `safeUrl`, with `target=_blank rel="noopener noreferrer"`. Everything else is a `<span>` (as `options/main.ts:171` does now).
- Restore never opens `chrome:`, `edge:`, `about:`, `file:`, `data:`, `javascript:`, `blob:`, `view-source:` or `chrome-extension:`. The result counts them as `skipped`, and the UI says what they were.

### 2.2 Importers (Edge Collections CSV, Pocket CSV/HTML, Toby JSON, bookmarks HTML)
| Rule | Value |
|---|---|
| Accepted files | `.csv .json .html .htm .txt`. A `.zip` gets "Unzip it first, then choose the .csv inside". No zip parser. |
| Max file size (checked on `File.size` before reading) | **20 MB** (bookmarks HTML of a heavy user is a few MB); same constant as `checkMsg` |
| Max tabs per import | **20,000** (refuse over, with the count and "split the file") |
| Max sessions / folders per import | **1,000** |
| Max JSON nesting walked | **32** |
| Max title / session name / group title | **1,000 / 200 / 100** characters (trim, single line: `\s+` → space) |
| URL | `safeUrl` only; others go to `skipped` with a reason |
| Output | Fresh objects with known fields only (`{url,title,pinned,groupKey}`). Never `Object.assign` or `for…in` over parsed data. Keyed lookups use `Map` (as `parseCsv` does). Reject `__proto__`/`constructor`/`prototype` as group keys. |
| HTML formats (bookmarks, Pocket HTML) | Parse **in the options page** with `DOMParser` (the service worker has no DOM; the offscreen alternative needs reason `DOM_PARSER`). Read only `a[href]` + `textContent` and `H3` folder names. **Never insert parsed nodes.** The explicit CSP `img-src 'self' data:` stops parsed `<img>` from calling out. Send the extracted plain list to the background, which re-validates it. |
| CSV | Reuse `csvRows` (RFC 4180). Strip the BOM. Find headers case-insensitively. The Edge Collections / Toby column and key names must come from a **real export sample in `tests/fixtures/samples/`**, not from memory (unverified here). |
| Preview before import | Counts of tabs, groups and skipped (with reasons). The import button stays disabled until the preview is OK (pattern 9, already in place). |
| Errors | Plain English, nothing changed, and the pasted text is kept. Never `String(e)`. |

### 2.3 Exports (Markdown, plain text, and CSV if added)
- **CSV:** every cell `"…"` with `"` → `""`. If the cell's first char is in `= + - @ \t \r ＝ ＋ － ＠`, prefix `'`. Start the file with a UTF-8 BOM (Excel shows Telugu/Hindi correctly). Use CRLF line ends.
- **Markdown:** `- [title](<url>)`. Escape `\ [ ] ( ) * _ \` < > # !` in titles and drop newlines. Percent-encode `<`, `>` and space in URLs. http(s) only (others as plain-text lines under "Can't reopen"). Headings per session/group are escaped the same way.
- **Plain text:** `url | title` per line (OneTab-compatible, so it re-imports), with title newlines turned into spaces.
- File names: `[^\w.-]` → `-`, ≤ 100 chars, built from the date (local) and session name. Download from the **page** with `Blob` + `a.download` (as `options/main.ts` does now), not a `data:` URL from the worker.
- Tests: hostile titles (`=HYPERLINK(...)`, `](javascript:alert(1))`, `<img onerror>`, 10k-char title, emoji, Telugu) round-trip as text.

### 2.4 Restore and the crash/update banner
- Above **100 tabs**, the page asks: "Open 1,240 tabs? They open asleep and load when clicked." The background has no hard cap, because big sessions are the core use.
- Skip-already-open uses an **exact URL match** (see HIGH issue). The result reports `alreadyOpen` with an "Open them anyway" action. Setting key `openDupes` is already in the WIP.
- One restore at a time: ignore a second `restore` while one runs (button disabled + background flag).
- The banner **never auto-restores**. It offers Restore / Dismiss, and dismiss is remembered (`banner-dismiss` exists in the WIP).
- The service worker may stop mid-restore. Make restore resumable or at least report partial counts, and keep nothing that matters only in memory.

### 2.5 Save window / picked tabs (menu + shortcut)
- `contextMenus.removeAll()` then `create()` inside `runtime.onInstalled` (avoids duplicate-id errors). Register `contextMenus.onClicked` and `commands.onCommand` **at the top level** of `defineBackground`. ≤ 6 top-level items. Contexts `action` (and `tab` only after a real-Chrome test).
- Shortcut: suggest **one** `Alt+Shift+<key>` that is free on Windows/Mac/ChromeOS Chrome (check the Chrome shortcut list before choosing). Show the current binding in options (`commands.getAll`) with "Change it in Chrome's shortcut page".
- Ignore repeated save commands within 2 s (idempotency). Skip incognito (as `captureAll` does). Confirm with the badge/notification text, not colour alone.
- Picked tabs = `tabs.query({highlighted:true, currentWindow:true})`. No new permission needed.

### 2.6 Messages (background)
- Every type is in `TYPES` (`lib/messages.ts`). `checkMsg` → `fromUs` → handler. Handlers re-check that the referenced id exists and that `wi`/`ti` indexes are inside the session.
- Pro features check `plan()` **in the background** (UI hiding is not security).
- Replies are always `{ ok, error? }`, and `error` is a fixed plain-English string.

### 2.7 Edit a saved session
- Every edit is one IndexedDB `readwrite` transaction. The undo copy is kept **in IndexedDB or `storage.session`**, not a worker variable (the worker can stop at any time).
- Add `updatedAt`. Two open pages editing the same session: the later write checks `updatedAt` and says "This session changed in another window. Reload."
- Drag to reorder needs a button alternative ("Move up / Move down / Move to…") per WCAG 2.5.7.

### 2.8 Storage and error recovery
- Wrap `putSession`/edits: on `QuotaExceededError`, reply "Your disk is nearly full, so Tab Lifeboat couldn't save. Free some space or download a backup." Set the icon warning and keep the user's input.
- Options shows `navigator.storage.estimate()` usage ("Using 14 MB").
- If the stale-snapshot badge (WIP `setBadge`) shows `!`, set `action.setTitle` to the reason, and the popup shows the same sentence (not colour alone, WCAG 1.4.1).

### 2.9 Supply chain and release (Akhil's part goes to the CEO queue)
- Build only from CI with `npm ci` (already done in `quality.yml`). Pin exact dev-dependency versions. Run `npm audit --omit=dev --audit-level=high` in CI. Run `npm audit fix` for the dev-tool findings now.
- **CEO queue (Akhil):** Chrome Web Store developer account with a passkey/security key. **Never approve a Google sign-in or "app access" screen that came from an email about the Web Store** (the Cyberhaven route). Check Google Account → Third-party access monthly.
- No remote code, remote config or CDN script. Updates ship only through the store.

### 2.10 Accessibility (popup ≤ 800×600, options at 390 px)
- Keyboard: every action reachable with Tab/Enter/Space; Esc closes dialogs; focus returns to the trigger.
- Visible focus ring (`--gold`), never hidden behind the undo bar or banner (2.4.11).
- Targets 44 px (Kalpa rule, above WCAG's 24 px).
- `aria-live="polite"` on preview counts, "Saved N tabs" and the search result count. `role="alert"` for errors.
- Labels on the search box and file inputs. Contrast 4.5:1 in light and dark. `prefers-reduced-motion` respected.
