# EA_XAUUSD code review: live readiness on The5%ers MT5 (2026-11-21)

**Scope:** `07-trading/ea/phase5/EA_XAUUSD/` (EA_XAUUSD.mq5, Core/, Guards/, Execution/, Intelligence/, Scoring/, Include/).
**Method:** I read the code by hand. MetaEditor isn't available here, so nothing was compiled or run. Each finding is backed by file:line.
**Target:** a live The5%ers High Stakes account trading XAUUSD 24/5 from a Wine/Linux VPS.

**Verdict:** **do not go live yet.** Two CRITICAL and nine HIGH items can lose money or breach the 5% daily or 10% max loss rules. The two CRITICAL items are a restart that wipes the daily-loss state, and weekend gaps that the code's own comment says can exceed the daily limit.

**Prop rule facts used:**
- The5%ers High Stakes page (fetched 2026-11-21) lists Maximum Daily Loss 5% and Maximum Loss 10%.
- The same page defines a profitable day as "Minimum (Midnight Balance or Midnight Equity - whichever is the lowest) - Previous Day Balance".
- **Unverified:** what the daily-loss limit is measured from (start-of-day balance, equity, or the higher of the two) and its reset time zone. The High Stakes page doesn't state them. Confirm with The5%ers support or the account agreement. Until then the fixes below use the most conservative reading.

| 1 | **CRITICAL** | Core/CPersistence.mqh:263-276; Core/CDailyStats.mqh:100-112, 65-68, 200-205 | **A restart wipes the daily-loss state.** (a) `ReadDaily` compares `reset_date` (a server date, from `TimeTradeServer`) with `TimeGMT()`. Between server midnight (21:00/22:00 GMT) and GMT midnight the dates differ. Any restart in that window (a Wine crash, a reconnect, re-attaching the EA, a VPS reboot) throws the file away. (b) Once the file is gone, `ResetForNewDay` sets `open_equity` to the current equity, so the day's earlier loss is forgotten. (c) The equity-based stop set by `ForceDailyLimit` (from FastSafetyCheck) is never saved. `Init` rebuilds the flag from `closed_pnl` (main magic only), so after any restart the EA trades again on a day it already stopped at -4%. | Compare server dates on both sides, and rebuild the day-open reference from deal history instead of trusting the file: `datetime d0 = DailyStats.ServerMidnight(); HistorySelect(d0, TimeCurrent()+60); double closed=0; for(int i=0;i<HistoryDealsTotal();i++){ulong t=HistoryDealGetTicket(i); long ty=HistoryDealGetInteger(t,DEAL_TYPE); if(ty==DEAL_TYPE_BUY\|\|ty==DEAL_TYPE_SELL) closed+=HistoryDealGetDouble(t,DEAL_PROFIT)+HistoryDealGetDouble(t,DEAL_SWAP)+HistoryDealGetDouble(t,DEAL_COMMISSION);} double bal0 = AccountInfoDouble(ACCOUNT_BALANCE)-closed; m_stats.open_equity = MathMax(bal0, m_stats.open_equity);`. Save the forced flag (`WriteKV(h,"forced_limit",...)`), and in `ReadDaily` use `TimeToStruct(TimeTradeServer(), today)`. |
| 2 | **CRITICAL** | Execution/CMixEngine.mqh:33 (comment), 341-345; Guards/CSessionGuard.mqh:160-169; EA_XAUUSD.mq5:370-376 | **Weekend gap can exceed the 5% daily loss.** At Friday 20:00 GMT the EA cancels mix pending orders but keeps every open position (mix positions hold up to 48 H1 / 20 H4 bars, and the main trade has no Friday exit). The mix open-risk cap is 2% and the main trade adds about 0.4% (more, see #3). The code's own comment puts the worst gap seen at 3.7x, which turns 2% into 7.4%. That is above the 5% **daily** limit and is booked against Monday. The comment only compares it with the 10% max loss. | Close or shrink positions before the weekend. In `OnTick`, when `ctx.is_friday && gmt_hour >= 20` (or 1 hour before `SymbolInfoSessionTrade` close), run `GuardCoordinator.CloseOpenPositionSafely("weekend_flat")` (it is private: add a public `FlattenAll(reason)`). | 3 | HIGH | Include/PriceUtils.mqh:116-126, 149-153; Execution/CPositionSizer.mqh:101-111 | **Rounding up to the minimum lot breaks the risk cap.** `NormalizeLot` and `ClampLot` raise any lot below 0.01 to 0.01. On a $10K account at 0.25%, 1 lot = $100 per $1: SL 80 pips gives 0.0031 lot, sent as 0.01, so **$80 risk instead of $25 (3.2x)**. After a loss (x0.75) and stage x0.4 the target is $7.50 and the real risk is 10.7x. On a $10K account the main strategy will almost always trade 0.01 lot at 1.2-3.2x its stated risk. | Refuse the trade instead of rounding up past a tolerance (the mix engine already does this): `double lot=MathFloor(raw/step)*step; if(lot<vmin){ if(vmin*sl_pips*PriceUtils.PipValue() <= 1.25*dollar_risk) lot=vmin; else return 0.0; } lot=MathMin(lot, Config.LotHardCap);`. | 4 | HIGH | Execution/CMixEngine.mqh:319-339, 380-381 | **Mix trades have no hard lot cap and no minimum stop distance.** Lot = risk / (dist x vpp) is capped only at `SYMBOL_VOLUME_MAX`. An EMA9 setup only needs `risk > 0.05*ATR`, and QM stops are `head - 0.1*ATR`, so a $0.30 stop on $25 risk gives 0.83 lot (8x `LotHardCap`). Spread ($0.20-0.40) is then already about 1R, and $2-3 of stop slippage in a spike costs about 10R (2.5% equity) on one trade. The risk calculation also ignores spread and commission. | `double min_dist = MathMax(PriceUtils.PipsToPrice(Config.SLPipsMin)*0.5, 3.0*(tk.ask-tk.bid)); if(dist < min_dist) return 0.0; lot = MathMin(lot, Config.LotHardCap);` and add spread to `dist` when sizing: `lot = risk_usd / ((dist + (tk.ask-tk.bid)) * vpp);`. |
| 5 | HIGH | EA_XAUUSD.mq5:344-348, 365; Guards/CGuardCoordinator.mqh:222-231, 290-306; Guards/CSystemHealthCheck.mqh:116-123, 360-367 | **The terminal states (PROFIT_TARGET, FATAL) switch off every safety check while positions may still be open.** `OnTick` returns before `FastSafetyCheck` once the EA is terminal. ## Checked and OK

- Every main order is sent with an SL (`CEntryEngine.mqh:144`, `CTradeCalculator.mqh`), and every mix market or limit order carries SL and TP at send time.
- Netting accounts are refused at init.
- Broker suffixes (`XAUUSD.x`) work because everything uses `_Symbol`.
- Emergency close uses a fresh tick, a filling mode the symbol supports, and deviation from `PipsToPoints`.
- Mix pending orders are counted in the open-risk cap.
- Calendar times are in trade-server time, which matches `TimeTradeServer()` (MQL5 docs).
